# Antifive — Inverse Gomoku AI GUI

[中文](README.md)

![Inverse Gomoku GUI screenshot](docs/prevpic.png)

**Antifive** is an open-source project for **Inverse Gomoku** (Chinese: 逆五子棋;
the player who first makes five in a row *loses*). It ships:

- a pygame GUI (human vs human / AI vs AI, review & branch replay, hints, clocks,
  synthesized sounds, `.afg` record save/load);
- a pure-numpy rules engine (plus a batched GPU mirror for training);
- four engines: uniform-prior MCTS, a self-trained policy/value network
  (**training failed**, kept for reproduction), a heuristic alpha-beta AI, and a
  KataGo integration with self-trained inverse-gomoku weights;
- an AlphaZero-style training pipeline (negative result, kept for study);
- weights: `.pth` for the failed self-trained net and `.bin` for KataGo.

## Rules

Inverse Gomoku is played on a 15×15 board. The standard rules:

1. Victory: whoever first makes five stones in a row loses.
2. Placement: Black moves first; players alternate placing stones on empty intersections.
3. Push (relocation): land on an opponent's stone, then move that stone along one of the eight directions for any number of cells, but it is blocked by other stones.
4. Prohibitions: White may not push during the first two turns (default; the
   white-restrict turn count is configurable in Settings, 0 = no restriction);
   suicide moves are forbidden; pushing with no valid path is forbidden.

> **Naming note**: this project uses the Chinese name 「逆五子棋」 (*Inverse
> Gomoku*) to distinguish it from *reverse gomoku*, which has no relocation
> rule. Both share the same losing condition (five in a row loses); Inverse
> Gomoku adds the capture-and-replace relocation mechanic. Full rules:
> [`docs/rules.md`](docs/rules.md) (Chinese).

## Web Version

Play in the browser, no installation:

**https://guijixzh.github.io/Inverse-Gomoku-GUI-vs-AI/**

- Pyodide (WASM) runs this repository's numpy engine and heuristic AI inside a
  Web Worker; the front end is a static TypeScript + Canvas site hosted on
  GitHub Pages.
- The first visit downloads the runtime (about 10-20 MB); later visits are served
  from a Service Worker cache. Three difficulty tiers map to heuristic depths
  2 / 4 / 8, defaulting to "Hard" (depth 8). The default limit mode is "AI clock"
  at 15 seconds per move (customizable); "no clock" performs a full-depth search,
  with a 180s/move safety cap in the browser (the desktop build has no cap).
- The settings dialog offers an **engine version** switch (Beginner classic /
  Mid enhanced / Advanced + distillation / Master defense-hardened /
  Legend = Master + distillation v2, default Advanced) and a **VCF
  forced-kill-chain** toggle (Mid/Advanced/Master/Legend). "Master" and
  "Legend" are engine versions (strength tiers above Advanced, combinable with
  any search depth), not difficulty entries, so there is no duplicated/
  overriding control. 15s/move calibration (anchor Beginner = 0 = 10 kyu):
  Advanced +182 (strongest tier), Master +121, Legend +74, Mid +61 — on the web,
  Advanced is strongest, unlike the desktop order Legend > Master > Advanced (see
  "Web and desktop are not the same engine" below). Master was displayed as
  "Hell" before 2026-10 (internal key stays `hell`).
- Settings can also adjust the **white-restriction turn count** (balance rule:
  White may not capture during its first N turns, default 2; 0 removes the
  restriction; applies to the next game) and the replay **auto-play** interval.
- Settings expose **AI variation** (off / low / mid / high / custom, default mid): the
  same position no longer always gets the same reply. `off` is strongest-move-every-time
  (bit-for-bit identical to the previous build); proven wins/kills are never
  randomised; variation is wider in the opening than in the middlegame; each game
  gets its own seed (reproducible via `moves + seed`). `custom` exposes every knob
  (T / value window / pool K / opening plies / book chance) and the engine clamps
  out-of-range values.
- A **pause/resume** button sits next to the AI clock (works in any live game and in
  AI-vs-AI spectating): pausing aborts the current think, freezes the countdown and
  stops further moves; resuming restarts the full configured countdown and re-thinks
  the turn (a notice is shown in the message strip). Without cross-origin isolation
  there is no interrupt, so the pause degrades to "let this turn finish, then hold".
- Feature parity with the pygame GUI: place/capture/relocate, danger hints, move
  numbers, relocation arrows, helper rays, two-click move confirmation (on by
  default), human resignation (two-click confirm), sounds, clocks, replay
  timeline with auto-play and branch trials, `.afg` import/export, and all four
  play modes.
- KataGo and the torch network cannot run in the browser; the web version ships
  the heuristic AI only.

### China access / mirrors

The Pyodide runtime (about 13 MB, most of the first load) is fetched from the
**npmmirror CDN** (`cdn.npmmirror.com`, Alibaba Cloud) by default, with automatic
fallback to the local copy / jsDelivr. Override the preferred source with
`VITE_PYODIDE_SOURCE=mirror|local|cdn` (production defaults to `mirror`,
development to `local`). The Service Worker caches mirror assets, so repeat
visits do not download them again. numpy and the engine wheel (about 3 MB) are
still served from the site itself; for optional full-site acceleration, upload
`web/dist` to any static host (e.g. OSS/COS) — the output is fully static.

Local development (Node.js 20+ and Python 3.10+; the wheel and Pyodide assets are
prepared automatically):

```bash
cd web
npm install
npm run dev      # dev server
npm run build    # static output in web/dist
npm run smoke    # browser smoke test after build (needs local Chrome/Edge)
```

Pushing to `main` triggers `.github/workflows/pages.yml`, which builds and
deploys to GitHub Pages. For a custom domain or a user site (`<user>.github.io`),
change `VITE_BASE` to `/` in the workflow.

## Project Status (read first)

- **v2.5 (2026-10) summary**: performance and cross-implementation parity.
  (1) Single-process speedups: Cython hot paths (1.5–1.8×) and root-node
  parallelism (2.9–5.3× with 4 workers), 15 s median nodes/move 16.4 k → 36.9 k,
  equal-time score vs the web 26.8% → 65.0%. (2) Desktop vs web, same tier and
  same 15 s wall clock, 200 games: 65.0% overall (lower tiers draw, upper tiers
  72–82%). (3) Web five-tier Elo calibration at 15 s (Advanced +182 strongest,
  Master +121, Legend +74, Mid +61, Beginner 0 anchor) plus a 2 s comparison
  (92 Elo span). (4) Web engine fixes: `uniformDepth` (same semantics as Python),
  the Master/Legend defense machinery ported, `hell` now uses distillation v1.
  (5) New cross-engine harness (`match_web_py` + `engine-bridge.mjs`) and a
  two-implementation quick-reference table in `docs/engines.md`.
- **v2.0 (2026-10) summary**: new fifth engine tier **Legend** = Master +
  KataGo distillation v2 (MLP value correction **replaces** the v1 value term;
  trained on 460 games / 7664 positions; offline value-sign 85.1%, policy
  top-1 45.2%) — 12s × 96 equal-time match: Legend **75 : 21** (78.1%) over
  Master. "Hell" was renamed **Master** (internal key/env vars unchanged);
  the four-tier UI became five tiers. New distillation-v2 pipeline
  (`build_distill2_data` record replay + two-tier hard-sample labeling,
  `train_distill2` D4×8 augmentation) with in-package weights; tuned
  parameters now ship inside the package (fixes the web silently falling back
  to built-in constants); also merged: configurable white-push restriction
  turns (0 = none) and replay auto-play.
- **Practical engines are the heuristic AI and KataGo.** The self-trained
  policy/value network (`network.py` + `training/`) **failed overall**: due to
  limited self-play data and compute budget, its strength stays at best slightly
  below the heuristic engine. Its code and weights (`models/warm_model.pth`,
  `models/best_model.pth`) are kept for reproduction and as a negative result;
  see [`docs/training-log.md`](docs/training-log.md) (Chinese).
- KataGo weights (`models/katago/*.bin`) are inverse-gomoku weights self-trained
  on top of [hzyhhzy](https://github.com/hzyhhzy)'s
  [KataGomo](https://github.com/hzyhhzy/KataGomo).
  `katago.exe` and CUDA/cuDNN runtime libraries are **not redistributed**
  (license and size); see [`docs/engines.md`](docs/engines.md) (Chinese).
- Developed on Windows / Python 3.13 / torch 2.9.1+cu130 / pygame 2.6.1 /
  numpy 2.2.6 (requires Python ≥ 3.10).

## Setup Check and One-Click Install (recommended)

The repo ships source, configs, and ready-made weights; third-party binaries
such as `katago.exe` are **not redistributed**. A stdlib-only helper is included:

```bash
python scripts/setup_env.py            # check dependencies and resource files
python scripts/setup_env.py --install  # install missing deps (GPU/CPU aware)
```

`--install` detects an NVIDIA GPU and installs the matching CUDA torch wheel,
otherwise falls back to CPU (`--cpu` forces CPU, `--torch-index URL` overrides
the index). The script also verifies weights/configs and reports whether the
KataGo executable and its DLLs are in place.

### Optional: enable the KataGo engine (shortest path)

1. Build/obtain `katago.exe` with inverse-gomoku rule support (source:
   KataGomo; GPU build additionally needs NVIDIA CUDA/cuDNN, neither is
   redistributed) — see [docs/engines.md](docs/engines.md);
2. Put `katago.exe` and its DLLs into `katago/` (or anywhere);
3. Launch the GUI → Settings → KataGo → use Browse to pick the executable,
   weight and GTP config → Confirm (paths are saved to the gitignored
   `config/engines.local.json` for this machine);
4. Re-run `python scripts/setup_env.py` to verify.

> Note: this repo does **not** include KataGo training programs or their
> dependencies; `models/katago/*.bin` are pre-trained weights, ready to play.

## Quick Start

```bash
python -m antifive                        # GUI (same as the `antifive` script)
python -m antifive --engine heuristic     # heuristic AI (depth 8 + 12s AI clock)
python -m antifive --limit none           # no clock (full depth 8, may be slow)
python -m antifive --model models/best_model.pth   # self-trained net as MCTS prior
python -m antifive --engine katago        # KataGo (place katago.exe yourself)
python -m antifive.cli --model models/best_model.pth --sims 400   # console play

pip install -e ".[dev,nn]" && pytest -q   # tests
```

On Windows you can also double-click [`run_gui.bat`](run_gui.bat) in the repo
root (adds `src/` to `PYTHONPATH` and launches the GUI; accepts the same flags).
If the default Python lacks dependencies, run
`python scripts/setup_env.py --install` first; alternatively create
`run_gui.local.bat` (gitignored) containing
`set PY="path\to\your\python.exe"`.

## Engines and Weights

A side-by-side quick-reference (implementation, mechanisms, Elo, head-to-head per tier
on desktop vs web) is in [`docs/engines.md`](docs/engines.md) (Chinese).

| Engine | Deps | Strength | Notes |
|---|---|---|---|
| Uniform-prior MCTS | numpy | Low | default fallback |
| Self-trained net MCTS | torch + `.pth` | Insufficient (training failed) | research only |
| Heuristic AI | numpy | Medium-high | depth 1–8 (Master/Legend deepen within the clock), default 8 + 12s AI clock; five versions: Beginner / Mid / Advanced / Master / Legend |
| KataGo (inverse gomoku) | external exe + `.bin` | High | recommended |

The heuristic AI needs no extra files (numpy) and comes in five tiers.

| Version | Key traits |
|---|---|
| Beginner | classic alpha-beta + global evaluation (no VCF / book / distillation) |
| Mid | search-consistency fixes + proof-based VCF kill-chain + KataGo opening book + root defensive VCF |
| Advanced (default) | Mid + KataGo-distilled value correction (tiny linear model predicts winrate, blended at 0.5) |
| Master | Advanced + deeper VCF (d12 / 240k nodes / ≤1.8 s) + strict-clock budget accounting with adaptive defensive reserve + clock-driven deepening; prophylactic candidates (P1) and latent-threat evaluation (P2) are kept behind switches and off by default (they lost equal-time A/B). Displayed as "Hell" before 2026-10 |
| Legend | Master + KataGo distillation v2 (when active, the MLP value term **replaces** the v1 term: on by default, weight 0.5; 5-cell pattern prior optional via `ANTIFIVE_PRIOR2_W`; `ANTIFIVE_DISTILL2=0` falls back to Master). 12s × 96 equal-time match: Legend 75 : 21 Master (78.1%) |

Historical 1 s/move equal-time Elo (96 games each; Beginner = 1000 anchor):
Mid ≈ 1340, Advanced ≈ 1650 (Advanced beat Beginner 98%, Advanced beat Mid 82%,
Mid beat Beginner 88%). At that budget the lower tiers were time-starved; at the
actual GUI/web budget (12–15 s) the tiers converge. Strict-clock 12 s × 96-game
results (seed 0; measured when Master was labelled "Hell"; Master no longer
overruns its own clock): Master beats Advanced 63:33 (65.6%, Elo +112), Mid
67:29 (69.8%, +145), Beginner 76:20 (79.2%, +232) — Master is the strongest
tier by every direct pairing. Relative Elo anchored at Beginner = 1000 via
direct matches: Mid ≈ 1154, Advanced ≈ 1022, Master ≈ 1232 (per-pairing
CI ≈ ±70 Elo; the frozen tiers show style inconsistencies at 12 s). Full table
and commands: `docs/engines.md`. Legend vs Master (12 s × 96): 75:21 (78.1%)
after switching distillation v2 to replace the v1 value term.

### Web and desktop are not the same engine

- Desktop tiers are five separate implementations (Beginner `heuristic_v2`,
  Mid `heuristic_v5`, Advanced `heuristic_v6`, Master `heuristic.py` — 2100+
  lines with defensive reserve, pre-gift blocking, proven-loss demotion and
  clock-driven deepening — and Legend `heuristic_v7` = Master + distill v2);
- Web tiers share one ~500-line alpha-beta, differing only in distillation tier,
  VCF depth/node cap, opening book and (Master/Legend) the ported defense
  machinery; the web search is 15–20× faster per node and reaches 200–400 k
  nodes per 15 s (desktop: 20–60 k), so deep search dilutes evaluation differences
  and the tiers bunch together;
- Hence **same-named tiers are not equivalent**: at 15 s the desktop "Advanced"
  already scores 75% against the web "Advanced".

### Single-process performance (2026-10)

- **Cython hot paths**: `python setup_fast.py build_ext --inplace` compiles
  `_shift` / `_line_maps_combo` / `_board_features` / `legal_mask_for` /
  `_line5_map_for` / `fwd_run_lengths` into an extension, **1.5–1.8×** single-process;
  falls back to pure Python automatically when the extension is missing, with
  bit-identical results (400 random states + fixed-depth move regression);
- **Root-node parallelism**: `ANTIFIVE_ROOT_WORKERS=4` (Advanced/Master/Legend),
  **2.9–5.3×** nodes per 15 s; default 1 keeps single-move behaviour unchanged;
- Combined, the 15 s median nodes/move went 16.4 k → 36.9 k and the equal-time
  score against the web went 26.8% (before) → 65.0% (after);
- `*.pyd` / `*.so` / `_fast.c` are build artifacts and not committed; the pure
  Python path still works without building.

Defaults and common switches:

- Desktop: "Advanced + VCF on", depth 8, 12s AI clock per move (flags
  `--heuristic-version/--heuristic-depth/--ai-time/--no-vcf`);
- Web: also "Advanced + VCF on"; difficulties = depths 2/4/8, default 15s AI
  clock, "no clock" runs a full-depth search (180s/move browser cap);
- White restriction (balance rule): default 2 turns, configurable in Settings
  (0 = White may capture immediately; applies to the next game). The desktop GUI
  restarts KataGo with `-override-config whiteRestrictTurns=<n>` so the engine
  always follows the game rules (verified via `kata-get-rules`);
- Parameters: `ANTIFIVE_TT_BITS` (transposition-table size, default 21; set
  19-20 in memory-tight environments such as the web), `ANTIFIVE_VCF=0` /
  `ANTIFIVE_VCF_DEPTH` (kill-chain toggle/depth, default 8; base budget
  `ANTIFIVE_VCF_BUDGET` 0.05s, widened to 5% of the move budget and capped at
  0.6s), `ANTIFIVE_NO_BOOK=1` (disable the opening book), `ANTIFIVE_VALUE_W`
  (distilled value weight, default 0.5), `ANTIFIVE_PRIOR_W` (policy prior,
  default 0 = off), `ANTIFIVE_NO_DISTILL=1` (disable distillation),
  `ANTIFIVE_NO_PARAMS=1` (skip the auto-loaded tuned parameters; the tuned set
  ships inside the package as `antifive/params.json`, so the web/Pyodide build
  and clean installs get it too; a desktop `data/params.json` (param_tune
  output) or `data/params_hell.json` (Master-only) overrides it), Master switches
  `ANTIFIVE_PREGIFT=1` / `ANTIFIVE_GIFT3=1` (P1/P2, off by default),
  `ANTIFIVE_NO_DYNAMIC=1`, `ANTIFIVE_HELL_VCF_DEPTH/NODES/TIME` (deep VCF,
  default d12 / 240k nodes / ≤1.8 s); Legend / distillation v2:
  `ANTIFIVE_DISTILL2` (on by default for Legend; set 0 to fall back to Master),
  `ANTIFIVE_VALUE2_W` (default 0.5, replaces the v1 value term),
  `ANTIFIVE_PRIOR2_W` (default 0 = off), `ANTIFIVE_ROOT_WORKERS` (root-node
  parallel workers for Advanced/Master/Legend, default 1 = serial).
  Distillation training pipelines (v1: build_distill_data → train_distill;
  v2: build_distill2_data → train_distill2) and engine/weight details: see
  [`models/README.md`](models/README.md) and
  [`docs/engines.md`](docs/engines.md) (Chinese).
